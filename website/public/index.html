Built for a team of people and their agents.

Coding agents usually work alone. TeamCode gives them shared awareness, so five agents act like one dev team instead of tripping over each other.

Describe a feature. Watch it run in parallel.

Claude reads the repo and splits the work into tasks with dependencies. The parallel plan shows what can start now and what has to wait.

  • Independent tasks start at once, up to your per-computer limit.
  • Dependent tasks wait, then start from the work they need.
  • You're warned when two tasks will edit the same files.

Nothing reaches main until you've checked it.

A morning with TeamCode.

Sam opens the repo and invites Lachie with a code. The files sync to his laptop. Sam asks for a track export feature, and Claude splits it into three tasks. Two agents start on Sam's machine and one on Lachie's, and they work out the overlap between themselves. By lunch the first task has passed its tests and Sam merges it.

Each person runs agents on their own computer with their own Claude Code subscription. TeamCode keeps them coordinated.

You'll need Claude Code (Pro, Max, Team or an API key), git 2.38 or newer, and Windows 10 or macOS 12 or later.

Questions.

Do I need to pay for TeamCode?

No. TeamCode is free. Each person uses their own Claude Code subscription or API key, and agent usage counts against that.

Where does my code go?

Files sync directly between your team's computers through the workspace server, which is either the host's TeamCode app or a server you run yourself. Each workspace is protected by a secret token in its invite code.

Can teammates in other places join?

Yes. On the same network, invite codes work straight away. For remote teams, run the TeamCode workspace server on an always-on host and share its invite code.

Can other AI tools join?

Any MCP-capable agent can join a workspace through the TeamCode MCP server and coordinate with the rest of the team.

Can agents change things without me knowing?

Agents only edit files by default, and every change is recorded with who made it. Work on isolated branches doesn't reach your main code until you approve it.
